# Design rationale

Why the project looks the way it does. `architecture.md` and the component specs say *what* is built; this file says *why*, with the evidence so far. Checked against the code on 2026-10-17 (CPLEX as the only solver, dilated initial neighbourhood).

## 1. Goal and setting
- Goal: construct shielding neighbourhoods (Schmitzer 2016) on unstructured planar point sets for MTW-type costs, with local "fences" around the target y = t(x_A), and prove that this is possible.
- Setting: discreteâ€“discrete OT between finite X, Y in R^2 (random tessellations, not grids). Schmitzer tested almost exclusively on Cartesian grids with a 4-neighbourhood; unstructured point sets in R^2 are essentially untested, and he reports that the variant without step-iii gets stuck on such point clouds. So step-iii (search for Y_hat) is always on.
- Squared Euclidean cost first, as the validated reference; MTW costs later through the same interfaces.

## 2. Why the shielding construction carries over to MTW costs
- Correctness of Alg. 5.1/5.2 holds for any cost: a shielding neighbourhood certifies global optimality (Cor. 3.10) independently of the cost. MTW only affects how sparse N becomes.
- Hence the core (shielding.py, multiscale.py, solvers) only calls `c`, `psi`, `psi_hat`. Everything Euclidean (bound (5.7), half-plane fences, candidate pruning) lives in `SquaredEuclidean`.
- MTW enters twice: (a) by Loeper, the unshielded set of a candidate is convex in the c-exponential chart at x_A, so fences stay convex there; (b) regularity of the optimal map, which is needed for the Lipschitz assumption in the sparsity bound (Prop. 5.3).

## 3. Hierarchy
**Option B (mesh-based, bottom-up) as the main hierarchy; option A (quadtree, Def. 4.4) as the baseline.**
- Our data is given at the finest level, so building bottom-up from the Delaunay mesh of the points is natural, deterministic and keeps a neighbour structure on every level (needed for S at coarse levels). k-means / top-down splitting was rejected for being random and ignoring the mesh, not for cost.
- The quadtree has a fixed cell geometry and uniform depth. On clustered data its fan-out is very unbalanced (up to 21 children at level 1 for 250 points), and `refine` builds children(x) x children(y), so the initial N1 explodes: clustered, n = 1000, |N1| / n = 28.7 at level 0 for the quadtree vs. 7.4 for the mesh (`hierarchy_measures.txt`). Both reach the dense optimum.
- **Coarse cost (4.2):** c_k(x, y) = c(rep x, rep y), as in Schmitzer, so every level is an ordinary OT problem and the shielding geometry applies unchanged on every level (Remark 4.8).
- **rep is an existing point** (the child rep closest to the mass centroid), not a new point as Schmitzer's cube centre. Reasons: for MTW costs the cost is only defined on Omega x Lambda (c-convex domains, which need not be convex in the plane), so a centroid could leave the domain; nested reps are also easier to debug. Cost: slightly larger rad. rad is computed exactly over the leaves, so (4.1) holds.
- **Matching:** two rounds of greedy matching along the shortest mesh edges give about 4 children per cell, close to a quadtree, and so comparable with Schmitzer.
- **Edge length cap (default 3.0) and attachment of leftovers:** without the cap, greedy matching pairs cells across gaps once nearby partners are taken, giving elongated cells (compactness up to 26 at level 1, uniform n = 4096) and weak bounds psi_hat. With the cap, max compactness drops to about 4, copy cells disappear (leftovers join a neighbour, at most 5 children), and the optimal cost is unchanged (`edge_cap.txt` (from the removed script edge_cap.py)).
- Compactness is measured per cell, rad / distance from its rep to the nearest other rep at that level, because a global mean spacing misjudges clustered data.

## 4. Candidate sets S(x_A)
- What matters is the cone constant q from Prop. 5.3 (5.6): the larger the angular gaps between candidate directions, the larger the fence P and Y_hat. The bound gives Y_hat inside a ball of radius about L D / q.
- **Decision (2026-10-17): Delaunay 1-ring as the default**, sector neighbours (`mesh.sector_neighbours`, nearest point per angular sector among the 32 nearest; filled sectors give q >= cos(2 pi / sectors)) as an option via `candidates=`. Measured at n = 4096 with warm start (`candidate_sets.txt` (from the removed script candidate_sets.py)), both unpruned: run time is a tie (8 sectors 3–9% faster, within the noise of iteration counts); the 1-ring gives the sparser N on clustered (-25%) and anisotropic (-19%) points, 8 sectors on the grid (-11%), uniform equal. The 1-ring's low q tail (5% quantile 0.19–0.37) matters less in practice than the empty outward sectors at cluster boundaries (1.4–3.6% of vertices with q <= 0 for sectors vs. 0.4–0.6% for the 1-ring). 6 sectors are the weakest variant. Tried and removed from the code: keeping only the 6 closest of the 8 sector neighbours. Dropping two sectors leaves angular gaps up to 135° (q 5% quantile 0.09–0.16 instead of 0.40–0.50), so Y_hat grows; it gave the largest N on uniform points (10.9 per point vs. 8.75 for the 1-ring and 8 sectors) and no gain on clustered, anisotropic or grid points. Covering all directions matters more than closeness to x_A.
- **Pruning** (`SquaredEuclidean(prune=True)`, `needed_candidates`): a candidate whose half-plane is not a face of the polytope P leaves Y_hat unchanged. First version dropped it for the search *and* its step-ii entry: N 10–25% smaller, but 25–40% more solve_sparse iterations (the step-ii entries let mass move between neighbouring targets and speed up convergence) and twice the shield time. Hence now (fix 2) the redundant candidates are skipped only in the search; step-ii keeps the entries of all candidates, so N and the iterations equal the unpruned run (measured). The remaining saving is search work, which does not pay off yet: shield time +40–45% because the check costs more than the search it saves; it can only pay off once the pruning check itself is vectorised over all x_A (now one small numpy call sequence per x_A, dominated by call overhead). Off by default.
- Boundary vertices have q <= 0 (P unbounded); this is accepted, as in Schmitzer (Remark 5.6).
- Later: adaptive 2-ring where 0 < q < q_min, as a comparison.

## 4a. Initial neighbourhood: dilated N1
- **Decision (2026-10-17):** N1 of each level is the refined coarse support dilated by one ring of the fine Y mesh (`multiscale.dilate`, default; `dilation=False` gives Schmitzer's N1).
- **Why so many iterations without it** (`experiments/iteration_analysis.py`, per iteration at level 0, 128 x 128): after the first coupling of a level about 70% of the points have the wrong target t(x), 10 (grid) to 24 (uniform) point spacings off (99% quantile). Each round of Alg. 4.1 can only move mass inside the local N, so the error shrinks by only 1–2 spacings per round, and on random points the fraction of wrong targets falls by only about 13% per round. The number of rounds is roughly the initial error divided by that, hence 12 (masked grid) and 29 (uniform) at level 0 against Schmitzer's median of 5 on grids. Ruled out as causes: solver tolerance (CPLEX at 1e-6 instead of 1e-9: identical iterations), dropping N between rounds (a cumulative N barely changes the count), the choice of S (the 4-neighbourhood saves at most one round).
- **Why dilation helps:** much of the initial error comes from the hard borders of the refined blocks children(x) x children(y); the fine optimum often sends mass just across them. With one ring of the fine Y mesh added, the first coupling can already do so.
- **Measured** (`iteration_variants.py` (script removed), 128 x 128, mesh hierarchy, 1-ring, CPLEX, repeated twice): iterations at level 0 from 29 to 8 (uniform) and 12 to 7 (masked grid); N1 grows from about 8 to about 20 entries per point, but N then no longer jumps (max |N| = N1, vs. 15 per point before); total time 140 s -> 55–58 s (uniform, -60%) and 79–82 s -> 63–65 s (masked grid, -20%); identical optimal cost.
- **Alternatives tested and rejected:** refining the coarse level's final shielding N instead of spt pi (N1 of 25–41 per point, no gain on uniform points); a two-phase solve_sparse (local rounds without the Y_hat search, then full shielding: phase 1 converges slowly, no gain at 128 x 128); a cumulative N (N_{k+1} = shield(pi) | N_k: same iterations, twice the N).
- **Not done on purpose:** stopping before the exact criterion. After round 4 the cost gap is already below 5e-7, but then N is not shielding for the final pi (no certificate, Cor. 3.10), and the map t is still visibly wrong (15% of the targets up to 12 spacings off on uniform points at round 12).

## 5. Shielding search
- `search_tree` is Alg. 5.2 done level by level with numpy: all cells of a level are tested against all candidates at once, then the surviving cells are expanded. It visits the same cells as the recursive version but avoids millions of Python calls. Measured: 25.7x fewer psi_hat evaluations than brute force (uniform, n = 2000). Since 2026-10-17 `shield` runs this for all x_A at once (`search_all`, frontier of (x_A, cell) pairs; the pruning check is batched the same way), in chunks of 4096 x_A because the peak memory is about 75 kB per x_A. A test checks that it gives exactly the N of the per-x_A loop. Shield time at n = 4096 dropped from 15–28 s to 6–13 s; with that, search pruning is roughly break-even (between -30% and +25% shield time depending on the point set), so it stays off by default.
- Strict inequality with tolerance: shielded only if psi_hat > psi(y_s) + tol, so rounding can only enlarge N, never make it wrong. Strictness is needed only for termination of Alg. 3.7 (Remark 3.9); ties occur systematically on grids, essentially never on random points.

## 6. Solvers
- Requirement: simplex only (interior-point solutions are not sparse), Python. Originally also floating point and open source (HiGHS); both given up, see below.
- **CPLEX network optimizer is the only backend** (since 2026-10-17, `solvers/cplex.py`, academic licence). It is Schmitzer's solver (network simplex) and at 128 x 128 about 2.2x faster per solve than HiGHS; HiGHS (`highspy`) was removed to keep the code small. Consequence: the code needs CPLEX Studio (academic) plus `docplex config --upgrade`; the PyPI Community Edition only handles 1000 variables. LEMON has no maintained Python binding; OR-Tools min-cost flow is integer-only and returns no duals.
- **Integer mass atoms stay** with CPLEX: refining needs the coarse coupling to meet its marginals exactly, which no floating-point LP solver guarantees (CPLEX's feasibility tolerance is 1e-6); with integer masses the basic solutions are exactly integral (total unimodularity), at no extra cost.
- **spt pi = all basic entries, including degenerate zeros.** They satisfy alpha + beta = c (2.4) and keep spt pi a spanning tree like a network simplex basis.
- **Warm start:** one persistent model per `solve_sparse`; new entries of N are added as columns, only nonbasic columns outside N are deleted, the solver continues from the old basis. Measured with HiGHS: solve time 128 s -> 6.7 s (uniform, n = 4096), same cost to 1e-16.
- Dense reference: `solvers.base.solve_dense` with CPLEX (tests); POT `ot.emd` as an independent check. Dense HiGHS took 250–520 s at n = 1000, multiscale 3–5 s.

## 7. Test problems and setup
- `problems.py`: points (uniform, clustered, grid, anisotropic) and masses (sums of random Gaussians, optional mask, small constant) are chosen independently, so geometric and mass difficulty vary separately; following Schmitzer Sect. 6.1. mu and nu are normalised to exactly equal mass.
- Code in a package (`src/msot`), tests with unittest, experiments as scripts with fixed seeds writing results and plots to `experiments/results/`, notebooks only for viewing.
- Parallelism: `N_WORKERS` (default 4) for independent experiments and block-wise checks; not inside one solve until profiling shows a need.

- Idea, not implemented (`cold_fraction`): with CPLEX at 256 x 256 (uniform, dilated N1, `large_65536_uniform_mesh_1-ring_cplex.txt`) the warm solves right after the first coupling of a level are slower than a cold solve: level 0 takes 85 s cold on 1.32 M entries, then 205, 194 and 97 s warm while N changes by several 100 k entries, and only 3–11 s once N has settled.
